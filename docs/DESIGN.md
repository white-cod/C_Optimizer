# C_Optimizer — проект программы очистки диска C:

Статус: черновик архитектуры, v0.1 (2026-10-31)

## 1. Цель

Desktop-приложение для Windows 10 (1809+) / Windows 11 (x64 и ARM64), которое:

1. **Само находит** всё, что занимает место и может быть удалено без вреда: кэши, временные файлы,
   остатки обновлений, предыдущие версии ОС, дампы, логи, кэши шейдеров GPU, кэши браузеров и приложений.
2. Показывает найденное с размерами, объяснением и **уровнем риска**, даёт выбрать и удаляет.
3. Работает на любой машине: никаких захардкоженных путей конкретного ПК — только переменные окружения,
   реестр, перечисление профилей пользователей и установленных программ.
4. Даёт анализатор диска (что занимает место) и системные инструменты (Windows.old, хранилище компонентов,
   гибернация, точки восстановления, зарезервированное хранилище и т.д.).

Главный принцип: **безопасность важнее мегабайт**. Лучше не удалить 200 МБ, чем сломать систему или потерять
пользовательские данные.

## 2. Технологии (рекомендация)

| Слой | Выбор | Почему |
|---|---|---|
| Язык / рантайм | **C# / .NET 10 (LTS)** | Нативный доступ к Win32/COM/WMI/реестру/сервисам, P/Invoke, зрелые библиотеки |
| UI | **WPF + WPF-UI** (Fluent-стиль, как у Windows 11) | Стабильно, без проблем деплоя WinUI 3, одинаково выглядит на Win10 и Win11 |
| MVVM | CommunityToolkit.Mvvm | Генераторы кода, минимум бойлерплейта |
| Win32 interop | CsWin32 (генерация P/Invoke) | Типобезопасно, не пишем сигнатуры руками |
| Графики | LiveCharts2 / собственный treemap на WPF | Диаграмма занятости, treemap анализатора |
| Логирование | Serilog (файл + окно лога в UI) | Отчёт о каждом удалённом файле |
| Тесты | xUnit + временные каталоги-«песочницы» | Тесты движка правил без риска для системы |
| Поставка | portable self-contained single-file `.exe` | Запускается на чистой Windows без установки .NET |

Альтернативы рассмотрены и отклонены: Electron/Tauri (тяжелее или требует Rust + IPC для каждой системной
операции), Python + Qt (плохая поставка, медленный обход ФС), WinUI 3 (сложный деплой, хуже на Win10).

```
src/
  COptimizer.Core        — модели, движок правил, сканер, планировщик удаления, безопасность

```

### 3.1 Ключевые абстракции

```csharp
interface ICleaner                       // один «пункт очистки»
{
    string Id { get; }                   // "gpu.nvidia.dxcache"
    CleanerCategory Category { get; }    // System, Browsers, GPU, Games, Apps, Dev, ...
    RiskLevel Risk { get; }              // Safe | Moderate | Expert
    Task<ScanResult> ScanAsync(ScanContext ctx, CancellationToken ct);   // только читает, считает размер
    Task<CleanResult> CleanAsync(ScanResult plan, CleanOptions opt, IProgress<CleanProgress> p, CancellationToken ct);
}
```

Два вида очистителей:

- **Декларативные (RuleCleaner)** — 90% случаев: «папка/маска + условия». Описываются в JSON, добавляются без
  перекомпиляции, база правил может обновляться отдельно от программы.
- **Программные (Special cleaners)** — то, что нельзя сделать удалением файлов: DISM, Windows.old, точки
  восстановления, корзина, гибернация, кэш Windows Update (нужна остановка служб) и т.д.

### 3.2 Формат правила

```json
{
  "id": "gpu.nvidia.dxcache",
  "name": "Кэш шейдеров NVIDIA (DirectX)",
  "description": "Пересоздаётся автоматически. После очистки первые запуски игр могут подтормаживать.",
  "category": "GPU",
  "risk": "Safe",
  "scope": "PerUser",                         // PerUser | Machine
  "detect": { "anyPathExists": ["%LOCALAPPDATA%\\NVIDIA"] },
  "targets": [
    { "path": "%LOCALAPPDATA%\\NVIDIA\\DXCache", "mask": "*", "recursive": true },
    { "path": "%LOCALAPPDATA%\\NVIDIA\\GLCache", "mask": "*", "recursive": true }
  ],
  "conditions": { "olderThanDays": 0, "skipLocked": true },
  "closeProcesses": [],                       // напр. ["chrome"] для кэша Chrome — предложить закрыть
  "keepFolder": true
}
```

`PerUser`-правила применяются к **каждому профилю** из
`HKLM\SOFTWARE\Microsoft\Windows NT\CurrentVersion\ProfileList` (переменные подменяются на пути профиля).

### 3.3 Конвейер работы

```
Сканирование (read-only, параллельно) → Результаты по категориям → Выбор пользователем
→ Предпроверки (процессы, блокировки, свободное место, точка восстановления*) → Очистка → Отчёт
```

## 4. Что чистим (база правил v1)

### Безопасно (Safe) — выбрано по умолчанию
- Temp: `%TEMP%` всех профилей, `C:\Windows\Temp` (файлы старше 24 ч)
- Корзина (все диски) — через `SHEmptyRecycleBin`
- Отчёты об ошибках WER: `ProgramData\Microsoft\Windows\WER`, `LocalAppData\CrashDumps`
- Дампы памяти: `C:\Windows\Minidump`, `C:\Windows\MEMORY.DMP`, LiveKernelReports
- Кэш эскизов и иконок (`thumbcache_*.db`, `iconcache_*.db`) — с перезапуском Explorer
- Delivery Optimization cache
- Загрузки Windows Update: `SoftwareDistribution\Download` (с остановкой wuauserv/bits)
- Логи: `Windows\Logs\CBS` (старые), `Panther`, `inf\setupapi*.log`, логи обновлений
- **Кэши шейдеров GPU**: NVIDIA `DXCache`, `GLCache`, `ProgramData\NVIDIA Corporation\NV_Cache`;
  AMD `DxCache`, `GLCache`, `VkCache`; Intel `ShaderCache`; системный `D3DSCache`
- **Остатки установщиков драйверов**: `C:\NVIDIA`, `C:\AMD`, `C:\Intel`, `ProgramData\NVIDIA Corporation\Downloader`
- Браузеры (кэш, НЕ куки/пароли/история): Chrome, Edge, Firefox, Opera/GX, Brave, Яндекс, Vivaldi — все профили
- Приложения: Discord, Telegram (кэш медиа — Moderate), Teams, Slack, Spotify, Zoom, VS Code (Cache/CachedData)
- Лаунчеры: Steam (`htmlcache`, `logs`, `dumps`, `shadercache` — Moderate), Epic, Battle.net, EA, Ubisoft
- Кэши UWP/Store-приложений: `Packages\*\AC\INetCache`, `LocalCache`, `TempState`

### Умеренно (Moderate) — показываем, не выбрано по умолчанию
- **Windows.old / предыдущие установки**, `$Windows.~BT`, `$Windows.~WS`, `$WinREAgent`, `C:\ESD`
  (после удаления откат к прошлой версии ОС невозможен — явное предупреждение)
- **Очистка хранилища компонентов WinSxS** — только через `DISM /StartComponentCleanup`
  (оценка через `/AnalyzeComponentStore`), НИКОГДА не удаляем файлы WinSxS напрямую
- Старые пакеты драйверов в DriverStore (через `pnputil`, оставляем текущие версии)
- Кэши разработчика: npm, yarn, pnpm, pip, NuGet, Gradle, Maven, Cargo (пересоздаются, но долго качать)
- Старые точки восстановления (кроме последней)
- Prefetch — по умолчанию не трогаем (бесполезно чистить, замедляет запуск)

### Эксперт (Expert) — отдельный раздел «Системные инструменты», с подтверждением
- `DISM /ResetBase` (после него обновления нельзя удалить)
- Отключение гибернации (`powercfg /h off`) или уменьшение `hiberfil.sys` (`/type reduced`)
- Отключение зарезервированного хранилища (~7 ГБ)
- Ограничение размера теневых копий / точек восстановления
- CompactOS / NTFS-сжатие (не удаление, а экономия 2–5 ГБ)
- Windows Installer `$PatchCache$`

### Только показываем, никогда не удаляем автоматически
- `Downloads`, `Desktop`, документы, большие видео/архивы — в анализаторе с кнопкой «открыть в Проводнике»
- Неиспользуемые большие программы и игры — список с размерами и ссылкой на штатное удаление

## 5. «Найти самому» — три механизма

1. **База правил** (раздел 4) — известные места, точный размер и описание.
2. **Официальные обработчики Windows Disk Cleanup** — перечисляем COM-обработчики из
   `HKLM\SOFTWARE\Microsoft\Windows\CurrentVersion\Explorer\VolumeCaches` и вызываем через
   `IEmptyVolumeCache` (`Initialize → GetSpaceUsed → Purge`). Это штатный способ Microsoft для
   «Предыдущих установок Windows», «Очистки обновлений», «Файлов журнала обновления», ESD-файлов и т.п.
   Плюс — автоматически подхватываются обработчики, которые есть на конкретной машине.
   Если обработчик отсутствует (cleanmgr объявлен устаревшим) — fallback на собственную реализацию.
3. **Эвристический детектор неизвестных кэшей** — при анализе диска ищем в `AppData`/`ProgramData`
   папки > N МБ с именами `Cache`, `Code Cache`, `GPUCache`, `ShaderCache`, `DawnCache`, `temp`, `logs`,
   `CrashReports`, `Crashpad`, `blob_storage` и т.п. Помечаются «Предположительно кэш», выбраны **не** по умолчанию,
   пользователь подтверждает вручную; найденное можно отправить в «свои правила».

## 6. Анализатор диска

- Быстрый обход: v1 — параллельный `FindFirstFileExW` с `FIND_FIRST_EX_LARGE_FETCH`;
  v2 — чтение MFT (`FSCTL_ENUM_USN_DATA`), как WizTree: весь диск за секунды.
- Учитываем реальный размер на диске (`GetCompressedFileSize`), hardlinks не считаем дважды (WinSxS!).
- Treemap + дерево папок + топ-50 больших файлов + фильтр по типам.

## 7. Безопасность (обязательные правила движка)

- Не следуем по reparse points / junction / symlink (иначе можно «уйти» в чужую папку).
- Жёсткий denylist: `Windows\System32`, `SysWOW64`, `WinSxS` (только DISM), `Program Files` (кроме явных правил),
  корни профилей, `Documents/Desktop/Pictures/...`, корень диска.
- Каждый путь из правила нормализуется и проверяется, что остаётся внутри разрешённой базы.
- Режим «пробный прогон» (dry run) — показать, что будет удалено, без удаления.
- Заблокированные файлы пропускаем, не ломаемся; итог «удалено X, пропущено Y (заняты)».
- Перед чисткой кэша браузера/приложения проверяем, запущен ли процесс, предлагаем закрыть.
- Опция: создать точку восстановления перед системными операциями.
- Подробный лог и отчёт каждой операции; удаление в корзину как опция для пользовательских файлов.
- Приложение работает с правами администратора (manifest `requireAdministrator`) — без них
  недоступна большая часть системных целей.

## 8. Интерфейс (экраны)

1. **Главная** — диаграмма занятости C:, кнопка «Сканировать», итог «можно освободить ~N ГБ», быстрая очистка Safe.
2. **Очистка** — дерево категорий с чекбоксами, размер, бейдж риска, описание, раскрытие до путей/файлов.
3. **Анализатор** — treemap, дерево, большие файлы, «предположительно кэш».
4. **Системные инструменты** — Windows.old, WinSxS, гибернация, точки восстановления, зарезервированное хранилище,
   CompactOS — каждая карточка с текущим размером и объяснением последствий.
5. **Программы** — установленные программы и игры по размеру (только переход к штатному удалению).
6. **История** — прошлые очистки, сколько освобождено, логи.
7. **Настройки** — исключения, свои правила, язык (EN), расписание (Task Scheduler), тема.

CLI: `coptimizer scan`, `coptimizer clean --level safe --dry-run`, `--report report.json` — для запуска по
расписанию и на других машинах без UI.

## 10. Принятые решения (2026-10-31)

- Стек: C# / .NET 10 + WPF + WPF-UI — подтверждено.
- Права: Release-сборка запрашивает администратора при запуске (`requireAdministrator`); Debug — `asInvoker`,
  в приложении есть кнопка «Run as administrator» и плашка «Limited mode».
- Перед удалением выбранные пункты пересканируются (план всегда свежий), затем показывается подтверждение
  с перечнем побочных эффектов и запущенных программ.
- Поставка: **только portable self-contained single-file `.exe`**, без установщика.
  Настройки, свои правила и логи хранятся в `%LOCALAPPDATA%\COptimizer`.
- Язык интерфейса и текстов правил: **только английский**.
- Режим удаления задаётся правилом (`deleteMode`):
  - `Permanent` — кэши, temp, логи, дампы и прочие регенерируемые данные (по умолчанию для правил);
  - `RecycleBin` — неочевидные файлы: находки эвристики «предположительно кэш», большие файлы из анализатора,
    пользовательские правила.

- Системная очистка (этап 3):
  - штатные обработчики Disk Cleanup (`IEmptyVolumeCache`) вызываются только по белому списку
    `VolumeCacheCatalog` со своими названиями и уровнями риска; `DownloadsFolder` и `User file versions`
    (пользовательские данные) и дублирующие правила обработчики исключены явно;
  - «Update Cleanup» (WinSxS через штатный механизм DISM) считается долго — анализ идёт в фоне, пункт
    появляется в списке по готовности;
  - кэш Windows Update — обычное правило с `stopServices` (wuauserv, bits) и `skipWhenRebootPending`;
  - корзина — отдельный очиститель (Moderate, не выбран по умолчанию).
